# 灵感与素材来源：设计说明

> 对应交互原型：`prototype/sources-paper.html`
>
> 这份文档回答三件事：来源怎么分层、数据怎么进来、界面和设置怎么让人敢用。

## 0. 当前实现（2026-11-25）

已经在真实插件里落地的部分：

- 第四个阶段「灵感」，地址 `#pms/inspiration`；
- 手动收件箱：收一句原话/链接，进 pending 候选；
- 作者门：`通过，进选题` 才调用 `createCard`；`略过` 不建卡；
- 搜索：按角度、理由、原话、来源名过滤；
- 素材库只读：从 `assets` 索引里搜标题/正文/路径，`收下` 只建 pending 候选，不复制原文件；素材库来源会显示「已接」并带文件数；
- 千帆笔记指标：`media_import_qianfan_notes` 可导入素材库内 CSV，按标题+发布时间去重，指标写入 `meta_json`，只作为证据；交易数据还没接；
- DSH 工具：`media_list_inspiration`、`media_search_inspiration`、`media_propose_inspiration`；助手只能提议，不能通过。

还没有做的部分，文档后面是目标设计而不是既成事实：

- 千帆互动/千帆交易的定时同步与界面导入；素材库目前是只读索引，不是定时增量同步；
- 文本/数据/交叉来源的自动提取与推荐排序；
- 插件内的助手对话面板；当前助手入口是 DSH 原生会话 + 上述工具；
- 交易数据的脱敏导入。

## 1. 先定一条底线

**素材库是事实，平台数据是信号，作者原话才是内容。**

这三类东西不能平权。素材库里的图片、问答、旧稿，能证明“这个问题存在”“这个说法有出处”；千帆的互动和交易数据，能提示“哪类题被收藏、哪类题带来成交”；但写什么、怎么说，只能由作者决定。

所以来源系统不应该是“一个更大的素材浏览器”，而应该是：

- 一个**只读的来源注册表**：知道每个来源在哪、什么时候同步、能读到什么；
- 一条**带出处的灵感流**：每条灵感都能回到原文件、原笔记或原始数据行；
- 一个**作者确认门**：数据可以排序、可以提问，但不能自动变成选题，更不能自动写稿。

## 2. 来源分五层，权威从高到低

| 层级 | 来源 | 作用 | 能不能进 AI 上下文 |
|---|---|---|---|
| 1 | 作者口述、整理角度（`WritingAngle_写作角度`） | 语气、判断、主线；最高权威 | 可以，但只能引用，不能改写 |
| 2 | 作者自己的历史发布（`Archive_归档_发布历史`、`Deliverables_发布定稿`） | 已验证的表达、标题、结构样本 | 可以，作为“我以前怎么说过” |
| 3 | 平台互动数据（千帆笔记明细、`xhs_stats_for_pgadmin.csv`） | 注意力、收藏、涨粉、商品访问的信号 | 可以，但只给数字/标题，不给因果结论 |
| 4 | 交易数据（订单、退款、客单） | 结果证据、商品结构 | 默认关闭；只给脱敏汇总 |
| 5 | 素材库（`Xhs_QA`、`Goods_Images`、课程讲义等） | 语料、截图、证据、配图 | 可以读摘要/OCR，不整库灌入 |

手动收藏（链接、截图、一句话）单独放“未验证”层：它是引子，不是证据。单条评论、单条笔记、单次成交都不能直接立项。

## 3. 数据模型

不复制素材库文件，只存“索引 + 出处 + 派生指标”。

```ts
type SourceKind =
  | 'material_library'   // 素材库，只读
  | 'angle'              // 作者口述 / 整理角度
  | 'xhs_notes'          // 千帆笔记互动
  | 'xhs_orders'         // 千帆交易
  | 'manual'             // 手动收藏

interface Source {
  id: string
  kind: SourceKind
  name: string
  root?: string            // 素材库路径，只在配置里出现一次
  adapter: string          // library-manifest / qianfan-csv / manual
  status: 'connected' | 'stale' | 'needs_import' | 'error'
  lastSyncAt?: string
  lastError?: string
  aiReadable: boolean      // 来源级开关
  schemaVersion: number
}

interface SourceItem {
  id: string
  sourceId: string
  externalId: string       // 文件相对路径 / 笔记键 / 订单哈希
  kind: 'file' | 'note' | 'order' | 'angle' | 'snippet'
  title: string
  excerpt?: string
  uri?: string             // 原文件路径或原帖 URL
  contentHash: string      // 用于幂等和去重
  publishedAt?: string
  capturedAt: string
  metadata: Record<string, unknown>
}

interface MetricPoint {
  itemId: string
  observedAt: string
  views?: number
  likes?: number
  saves?: number
  comments?: number
  shares?: number
  follows?: number
  coverCtr?: number
  avgWatchSeconds?: number
  shopVisits?: number
  paidAmount?: number
  orders?: number
  refunds?: number
}

interface Candidate {
  id: string
  title: string
  angle: string
  evidenceItemIds: string[]
  status: 'inbox' | 'shortlisted' | 'card' | 'draft' | 'rejected'
  authorConfirmedAt?: string
}
```

三条硬规则：

1. `externalId + contentHash` 唯一，重复同步只更新 `observedAt`，不新增重复项。
2. 指标是**时间序列**，不是覆盖。10 月 6 日的 624 次观看和今天的观看数要能同时存在。
3. 每条 `Candidate` 必须能列出 `evidenceItemIds`；列不出来的，不允许进入选题库。

## 4. 四个连接器

### 4.1 素材库：读索引，不读整库

素材库 `D:\Coding\一个路人甲小红书素材库` 有 15 个子库、6,551 个文件、约 1,969 MB。它已经有：

- `_Index_索引/manifest.json`：子库、文件数、用途、消费者；
- `_Index_索引/素材索引.md`：人读的目录；
- `_Index_索引/build_index.py`：索引管线；
- `_Index_索引/目录规范.md`：三层分离、不复制资产、`XHS_LIB` 常量、每月 md5 备份。

连接器只做三件事：

1. 读 `manifest.json` 和索引，建立文件级 metadata；
2. 对需要的文件生成摘要/OCR 缓存（写在自己的数据目录，不写素材库）；
3. 提供 `open original` / `reveal in library`，不复制、不改名、不移动。

禁止扫描 `Coaching_*`；禁止把 `Goods_Images` 的图直接当公开素材；禁止把 `Deliverables` 当“灵感”，它是已发布结果。

### 4.2 口述与角度：最高优先级

`WritingAngle_写作角度` 是成对的：

- `01_口述原文_金句想不起来_20261120.md`
- `02_整理版角度_金句想不起来_20261120.md`

整理版明确写了：它只是结构化大纲，不是成稿，正文由作者写。系统要做的是：

- 把“原话”和“整理”分两个字段存，不合并；
- 引用时默认引原话，整理版只做结构提示；
- 任何“润色/改写”按钮都不应该出现在这里。

### 4.3 千帆笔记互动：笔记级信号

`笔记列表明细表.xlsx` 的字段是：笔记标题、首次发布时间、体裁、曝光、观看量、封面点击率、点赞、评论、收藏、涨粉、分享、人均观看时长、弹幕。

导入后做三件事：

- 统一字段名，保留原始列；
- 计算派生指标：收藏率、互动率、涨粉率、商品访问率；
- 和 `xhs_stats_for_pgadmin.csv` 的 `shop_visit_count` / `shop_paid_amount` 对齐，但标注“笔记级归因，弱”。

样例（真实数据，只作为原型里的信号）：

- “面试语速太快 声音像人机怎么调”：曝光 5,821，观看 624，封面点击率 10.9%，点赞 26，收藏 13，商品访问 0；
- “面试没人对练 一个人怎么练”：曝光 6,745，观看 695，封面点击率 10.3%，点赞 45，收藏 31；
- 历史 280 篇：总观看 1,648,467，总成交 74,790.19 元，观看中位数 1,524.5。

这些数字能提出假设，比如“高点击、低商品访问，是不是正文没接住？”，但不能直接得出“这类题不能写”。

### 4.4 千帆交易：结果证据，不是灵感

订单表通常没有 `note_id`。没有就直接说没有：

- 有 `note_id`：笔记级归因；
- 只有日期/商品：日期级或商品级归因；
- 都没有：只做账号级汇总，不假装是某篇笔记的功劳。

默认脱敏：订单号哈希、买家信息丢弃、金额只进聚合。AI 默认读不到明细。

## 5. 归因和样本量必须露出来

每条数据型灵感都带三个标签：

```text
来源：千帆笔记明细 · 2026-09-25
归因：笔记级（shop_paid_amount 回填）
样本：n=1
```

显示规则：

- `n < 3`：只能说“样本”，不能说“规律”；
- 只有日期级归因：禁止写“这篇笔记带来了 X 元”；
- 数据超过 30 天：打“可能过期”，并显示最后同步日；
- 头部样本：同时显示账号中位数，避免只看到 26 万观看的那条。

## 6. 界面：一条流，不是五个浏览器

原型 `prototype/sources-paper.html` 的结构：

```text
┌ 顶栏：纸 / 选题 草稿 渲染 灵感 / 同步 来源设置 ┐
├ 左：来源（全部 / 你的口述 / 素材库 / 千帆互动 / 千帆交易 / 手动）
├ 中：搜索 + 筛选 + 新鲜度提示 + 灵感流
└ 右：详情（出处、指标、归因、作者确认、转成选题）
```

交互原则：

1. **来源是过滤器，不是文件夹树**。不要让人一层层点进 `Xhs_QA/2024/03/...`；统一搜索，来源只做筛选。
2. **每条都有出处**。详情里第一块是路径/URL、日期、归因方式；没有出处的条目不允许“转成选题”。
3. **数据型条目先给“观察”，再给“假设”**。例如“收藏率 5.6%，商品访问 0；可能正文给了情绪，没给动作”。不直接给标题。
4. **“转成选题卡”是草稿，不是发布**。生成后进入选题库，仍需作者确认、补角度、补素材。
5. **手动收藏允许不完整**。没有链接、没有数据也能存，但标“未验证”，并提示“再找一个样本”。
6. **收进灵感是全局动作**。快捷键 `⌘K` / `/` 聚焦搜索；任何页面都能把一句话、一个链接丢进同一个 inbox。

## 7. 工具设置：让人知道边界

原型里的“来源设置”分四组：

### 已连接

- 素材库：路径、只读、文件数、重新索引；
- 口述与角度：路径、只读、原话优先；
- 千帆互动：导入、字段映射、最后同步；
- 千帆交易：导入、脱敏、归因方式。

### 同步

- 素材库：每天/每周/手动；监听 manifest，不扫内容；
- 平台数据：千帆没有开放 API，先手动导入；可设“每周提醒”；
- 失败重试：保留上一次成功快照，不把空结果当“已同步”。

### AI 可读范围

- 作者原话：允许/不允许；
- 素材摘要：允许/不允许；
- 笔记互动：允许/不允许；
- 交易数据：默认关闭；打开也只给脱敏汇总。

### 隐私与保留

- 订单号/买家信息：写入前哈希/丢弃；
- 原始导出：只留在本地数据目录，不上传；
- 保留：指标时间序列保留 24 个月；原始快照可手动清理；
- 删除来源：删索引，不删原文件。

## 8. 不要做什么

- **不要把素材库复制进项目**。6,551 个文件、1.9 GB，复制一遍就失去“唯一事实源”，还会让备份和权限变复杂。
- **不要让数据自动决定选题**。数据只能排序、提示、提问；`商品笔记创作流程` 里写得很清楚：作者是唯一内容决策源，agent 不判断质量，也不填【待你定】。
- **不要用单条笔记证明因果**。尤其“这篇带来 9,147 元”这种话，除非有订单级归因。
- **不要把交易数据当灵感**。交易是结果，不是内容；它能告诉你“什么在卖”，不能告诉你“该怎么讲”。
- **不要做五个互不相通的浏览器**。素材库、千帆、口述、手动收藏必须能在同一条流里搜到。

## 9. 落地顺序

1. **索引层**：`sources` / `source_items` / `snapshots` / `metric_points` 四张表；素材库 manifest 导入；手动收藏。
2. **界面层**：来源过滤器 + 统一搜索 + 详情出处 + “转成选题卡”草稿（不接自动分析）。
3. **千帆互动**：CSV/XLSX 导入、字段映射、笔记级指标、样本量/新鲜度标签。
4. **交易**：订单导入、脱敏、归因标记；先做“日期级”，不急着做“笔记级”。
5. **作者确认门**：候选卡必须由作者确认才能进选题库；记录 `authorConfirmedAt`。
6. **再接 AI**：只读允许的来源，生成“观察/假设”，不生成成稿；每条引用带 `SourceItem.id`。

## 10. 还需要你定的三件事

1. 千帆交易数据你手上是**订单明细**还是**按日/按商品的汇总**？这决定归因能做到哪一级。
2. 素材库的 `Xhs_QA` 和 `WritingAngle` 是否允许 AI 读全文，还是只读摘要/前 N 行？
3. “灵感”是独立一屏，还是并进选题库做一个来源筛选？原型先做了独立一屏，因为来源管理本身有设置和同步，塞进选题库会挤。
