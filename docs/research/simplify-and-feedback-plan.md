# 精简与反馈：可以照着改的设计方案

> 结论先行：**"杂"是每一层都在同时说话，"弱"是动作之后界面没有回应。**
> 解法不是重做视觉，是两套纪律——**配额**管精简，**反馈闭环**管手感。

---

## 0. 一个判断标准：一屏只回答一个问题

| 屏 | 唯一要回答的问题 |
| --- | --- |
| 看板 | 哪张该现在写？ |
| 卡片 | 我该怎么想？ |
| 改稿 | 这句怎么写？ |
| 渲染 | 这一页好不好看？ |

**任何元素，如果不能帮助回答当前问题，就降一级**：进折叠、进 `⋯`、进 hover、进下一层。
这是后面所有取舍的依据，不再逐项争论。

---

## 1. 为什么现在"杂"：三个根因

**① 同一语义出现在多个位置**

| 语义 | 现在出现的地方 |
| --- | --- |
| "这张卡到什么程度了" | 看板 `进行中` + 看板 `种子阶段` + 卡头 `进行中` |
| "引擎健不健康" | 顶栏 `本地预览引擎` + 卡头 `模型分析` + 分析栏又一处 |
| "写了多少" | 卡头 `4 条原话` + 时间线本身 + 分析栏底部建议 |

同一个事实说三遍，用户就得比对三遍。**一个事实只说一次，说在它被用到的地方。**

**② 所有层同时展开**
分析栏 6 段全展开、看板摘要 8 行、工具栏 6 按钮平铺、composer 6 个动作同级。展开=平等，平等=没有重点。

**③ 视觉权重没有分级**
胶囊（badge）和主按钮都是"有底色的块"，在视觉上是同一种东西。当一屏出现 6 个"有底色的块"，人就找不到主路径了。

---

## 2. 精简：用配额，不靠感觉

| 配额 | 数值 | 现在超标的地方 | 超出怎么办 |
| --- | --- | --- | --- |
| 实心主按钮 | 每屏 **≤1** | 卡工作区暂存/成熟/追加保存三选一不清 | 只留「标为成熟」 |
| 彩色徽标 | 每屏 **≤2** | 卡工作区 4 个 | 状态改圆点，引擎只在降级时出现 |
| 语义色 | 每屏 **≤3** | accent + warn + success + danger 同时 | danger 收进 `⋯`，不常驻 |
| 正文字号 | **4 档**（12 / 13 / 15 / 18）+ 陈述句 33 | 现有刻度已收敛，执行即可 | 不再新增 |
| 工具栏动作 | **≤3** | 改稿 6 个平铺 | 1 主 + 2 次 + `⋯` |
| 卡片正文 | **≤2 行** | 看板 8 行 | 改用一行证据 |
| 看板一屏可见卡 | **≥12 张** | 现在约 6 张 | 分组 + 三档密度 |
| 数字 | `tabular-nums` + 拉丁衬线 | 计数、字数、页码 | 统一一个令牌 |

**执行方式**：把这些写进 `docs/DESIGN-SYSTEM.md` 新增一节"配额"，并在规范页加一个自检快照——不是口头约定。

## 3. 反馈：一个闭环，替换掉现在三种散落的实现

现在反馈散在三处：`pms-toast`（成熟/删除）、按钮 `disabled`、`badge 整理中`。语义不一致，位置也不一致。

统一成**四拍**：

| 拍 | 时长 | 做法 |
| --- | --- | --- |
| ① 按下 | 0–80ms | `:active { transform: scale(.97) }`，所有可点元素 |
| ② 进行中 | 立即 | 按钮内 12px spinner，**文案不动、宽度不变** |
| ③ 结果 | 200ms 衰减 | 局部高亮 + 一句**带数量**的回执 + 可撤销 |
| ④ 失败 | 立即 | 行内红 + **保留输入** + 重试入口 |

配套五条纪律：

1. **乐观更新先行**：先在界面上做出来，后台再校准；失败回滚。追加原话、标为成熟、删除卡都走这条路。
2. **一屏至多一个"进行中"**，且它必须在动作发生的位置（不要顶栏一个、按钮一个、侧栏一个）。
3. **回执带数量**：「已追加 1 条原话 · 共 5 条」，而不是「保存成功」。
4. **撤销在 toast，确认在弹窗**：可逆动作一律"先做 + 可撤销"，只有不可逆（删除已导出稿）才弹确认。现在的删除走 toast 撤销，方向对。
5. **有重量的动作给一次微动画**：成熟的金色骑缝章已经很好，保留；追加原话补一个"新节点高亮衰减"，让"我写的东西进去了"可感知。

## 4. 分屏改造

### 4.1 看板
- 顶部加一行陈述句（33px / 300）：`今天该写的是这 3 张 · 问答池新增 2 个方向`。
- 卡片：色条 + 标题（2 行）+ 一行证据 + 事实带；标签只留 1 个。
- 分组：`该写了` / `在写` / `搁置`；密度按容器宽度自动降级。

### 4.2 卡工作区（对应上面的对照图）
- 卡头：标题 + 一行事实带（`● 在写 · 4 条原话 · 3 天前动过`），三个胶囊全部去掉。
- 新增一条**提示条**：`现在最该补：一个具体案例 →`（取 `analysis.gaps[0]`），点开右侧抽屉看完整分析。
- 分析栏：**默认抽屉关闭**，不再与正文并排占 320px。打开时只显示「核心判断 / 还缺什么 / 相关素材」三段，其余折叠成计数行。
- composer：右侧只有「暂存」（次）+「标为成熟」（主，唯一实心）；「追加保存」改为失焦自动保存；「进入聚焦」「删除」收进 `⋯`。
- 输入框 placeholder 改成有引导的话：`接着上面说，想到什么写什么`。

### 4.3 改稿
- write / read **合一**：默认阅读态，点哪段改哪段（`<AutoText>` 失焦提交），不再切模式。
- 侧栏三个 tab 收成：默认只显示「建议」，大纲折叠在正文左侧小目录，版本收进 `⋯`。
- 工具栏：唯一 primary 是「送去渲染」，其余降级。

### 4.4 渲染
- 「导出」为唯一 primary。
- 每页 PNG 生成完播一次显影（`blur(10px) scale(1.03)` → 清晰，0.9s）；未生成页显示页码水印。
- 素材面板已是抽屉，保持。

## 5. 一周落地（每天可验收）

| 天 | 做什么 | 验收 |
| --- | --- | --- |
| D1 | 反馈闭环 + 乐观更新（卡工作区三动作） | 追加原话 200ms 内出现，失败可回滚且不丢输入 |
| D2 | 看板与卡片精简（标签 1 个 / 摘要 2 行 / 事实带 / 分组） | 一屏 ≥12 张，彩色徽标 ≤2 |
| D3 | composer 与工具栏收纳 + 按钮不跳字 | 卡工作区只剩 1 个实心主按钮 |
| D4 | 分析栏抽屉化 + 顶部提示条 | 默认视野里没有分析栏；提示条可点开 |
| D5 | 改稿合一 + 渲染显影 + 规范页补「配额」节 | 改稿不再切模式；配额写进文档 |

---

## 6. 验收标准（量化）

- 卡工作区首屏：彩色元素 ≤3，可见按钮 ≤4。
- 任一动作 **200ms 内**有视觉回应（不等网络）。
- 任一写操作有**带数量的回执**，且可撤销。
- 看板一屏 **≥12 张**卡。
- 全程键盘可用：`Tab` 可达、`Enter` 提交、`Esc` 分层退出。
- `prefers-reduced-motion` 下无位移动画。
