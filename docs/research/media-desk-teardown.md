# dsh-media-desk 拆解：哪些值得抄，哪些别碰

> 研究对象：`woniuniuniu/dsh-media-desk` v2.7.x（MIT），2026-11-05 被 DeepSeek Harness 官方点名的 4 个插件之首。
> 本文只讨论对 `dsh-personal-media-studio` 有用的部分。代码位置以克隆下来的仓库为准（`D:/Coding/_research/media-desk`）。
> 规模参考：`client/` ≈ 5.5k 行（`styles.css` 845 行，最大单文件 `studio.jsx` 611 行），`src/` ≈ 3.4k 行。

---

## 0. 一句话结论

它的优势不在功能多，而在**把一次生成做成了可以观看、可以局部返工的过程**：先把版面排好，四块内容同时往里长，每一块都能单独重画，每一步都有回执和撤销。

我们的产品在"判断质量"和"人工 gate"上比它硬（素材库只读、原句不改、成熟必须人工点），弱在三件事：

1. **过程不可见**——后台一跑就是"正在生成文稿…"，用户不知道它在读什么、写到哪。
2. **改稿要切模式**——write / read 互斥，想改一句得先切回编辑态。
3. **卡片不可辨认**——看板上一屏十几张同构卡片，只有字，没有"这是截图卡还是我的判断"的视觉区分。

优先抄这三件，其余按 P0/P1/P2 排。

## 1. 它是怎么搭的（决定哪些能抄）

| 层 | 做法 | 对我们的含义 |
| --- | --- | --- |
| 界面 | React 单文件 hooks，无路由库；`view` + `focusId` 两个字段决定显示什么 | 我们已经是 `stage` + `cardId` + 哈希，结构更正规，不用改 |
| 状态 | 自建 `useSyncExternalStore` 快照（`desk.js`）；写操作统一走 `dispatchOps(ops[])`，服务端返回**整个新 state + receipts** | 我们的 RPC 是逐方法调用。它的好处是**天然有回执文案和撤销标签**，这是全局撤销的前提 |
| 样式 | 单个 `styles.css`，`md-` 前缀 + BEM-lite；颜色全走宿主 `--dsw-alias-*`，圆角/阴影用宿主 elevation token | 我们已经有 3 层令牌体系，比它规范。它值得学的是"**只用宿主语义色**"这条纪律 |
| 任务 | Host 内 job + `AbortController`，浏览器 700ms 轮询 `production` | 我们也是轮询 + job 表，但**没有把 job 拆成可命名阶段**暴露给界面 |
| 生成 | 先一次轻量 `plan` 调用（maxTokens 3000）产出标题/封面字/配图 prompt/分镜，再让文章 + 所有图片**并行**推进（worker 池 + 单图 429 退避） | 我们是一次 LLM 出全文再规则分节。这是最值得改的一点（见 4.1） |
| 兜底 | plan 失败 → `backup` 模板继续；文章失败 → 结构草稿 + 提示；生图未配置 → `skipped` 不阻塞 | 我们只有"整体成功/失败"两态，没有"部分成功" |

**结论：它没有比我们更复杂的技术，优势全在状态颗粒度和交互密度。** 我们的 SQLite + 17 表 + 幂等推进其实更重。

## 2. 交互体验：10 条可抄

### 2.1 卡片 → 工作区的共享元素转场
**它怎么做**：点卡片时把卡片的 `getBoundingClientRect` 记进 `sheetOrigin`，工作区用 `clip-path: inset(...) round 20px` 从那个矩形展开到全屏；返回时反向收回去（`studio.jsx:562-574`）。
**我们现在的差距**：看板点开直接换组件，没有空间连续性，用户会短暂失去"我从哪来"。
**怎么落**：`readRoute` 时顺手把触发元素 rect 存进 state，`CardWorkspace` mount 时用 Web Animations 播一次 `clip-path`。纯前端，约 40 行。
**成本**：低｜**收益**：中高（每次进卡都发生）

### 2.2 生成过程 = 四块同时长 + 进度像助手在汇报
**它怎么做**：点「一键成稿」后，右栏的标题区、脚本区、分镜六格**先按最终版式排好骨架**，然后同时填充。左栏底部出现 4 行进度：`标题和封面字 ✓` / `正在写 367 字`（shimmer 扫光）/ `封面和配图 2/9` / `分镜 3/6`，完成项打勾圆点。每行都是"动词 + 数量"，不是"处理中"。
**我们现在的差距**：后台分析只有一个「整理中」badge + 一句"正在后台整理这张卡"；改稿只有一行"正在生成文稿…"。
**怎么落**：把 `job` 的 stage 从 `queued/running` 扩成有名字的阶段（读素材 → 抽判断 → 找缺口 → 写第 N 节 → 配图匹配），界面用 `pms-progress-step` 列表渲染，完成打勾、当前项扫光。后端已有 job 表，加一个 `stage_detail` 字段就够。
**成本**：中（后端 +2 字段，前端 +1 组件）｜**收益**：最高。这是把"等待"变成"信任"的地方。

### 2.3 选中一段 →「让助手改这段」
**它怎么做**：在正文里划选 ≥4 字，选区上方浮起一个胶囊按钮；点它把选中文字塞进 `chatQuote`，输入框顶部出现引用条（`目标：xxxx ✕`），发送时拼成「关于这段『…』：<要求>」，模型只改这段。
**我们现在的差距**：建议只能整篇给，用户得自己在正文里找位置。
**怎么落**：`pms-reading` / 改稿正文加 `onMouseUp` 取选区 → 浮层 → 输入框引用态；提交走现有 `suggest` 通道，带 `span` 范围。注意别破坏"原句不改"——这类改动要显式标成"建议"，仍需用户点采纳。
**成本**：中｜**收益**：高（改稿阶段最值钱的交互）

### 2.4 就地编辑：失焦即存，不点"编辑"
**它怎么做**：标题、正文、灵感正文都是 `AutoText`——一个自增高 textarea（`rows=1`，`scrollHeight` 撑开），`onBlur` 才提交，值没变就不发请求。
**我们现在的差距**：改稿页 write / read 互斥，改一句要切模式；卡头标题不可编辑。
**怎么落**：抽一个 `<AutoText>` 到 `components`，标题、卡名、小节标题默认就地可编辑；提交走 `advanceCard`/`updateX`，失败回滚。
**成本**：低｜**收益**：高

### 2.5 全局撤销 + 带标签的 toast
**它怎么做**：每个写操作都带 `label`（「修改标题」「切换风格」），服务端留 ops 栈；toast 显示回执并带「撤销」；`Cmd/Ctrl+Z` 在非输入态直接撤上一步。
**我们现在的差距**：只有两处撤销（删除→恢复、成熟→退回选题），且不可组合。
**怎么落**：短期不必上 ops 栈，但**先把 label 规范化**：每次 RPC 都给一句人话回执，toast 统一显示。中期再做 `ops` 表和 `undo` 端点（我们已有 `client_op_id` 幂等，底子比它好）。
**成本**：中高｜**收益**：中

### 2.6 一块放大（FLIP）+ 大图左右键
**它怎么做**：脚本/分镜格子点放大 → 从原位 interpolate 到铺满，其余格子降到 25% 不透明度；Esc 收回原位；大图查看器支持 ←/→ 在封面、配图、分镜之间连续翻。
**我们现在的差距**：渲染阶段是 iframe 全屏编辑器，没有"局部放大细看"这一层。
**怎么落**：改稿正文与素材清单加"放大阅读"（限宽 700→900）；素材预览加左右键。
**成本**：低｜**收益**：中

### 2.7 分层 Esc + 焦点回还
**它怎么做**：Esc 有明确层级：先收大图 → 再收放大格 → 最后才退工作区；判断依据是 `document.querySelector('.md-tile.is-open,.md-viewer')`。
**我们现在的差距**：`FocusConfirm` 已经做了焦点陷阱和回还，但页面级 Esc 还没分层。
**怎么落**：一个 `useEscape(layers)` 小 hook，按栈顺序消费。
**成本**：低｜**收益**：中（键盘用户感知明显）

### 2.8 空态即教学 + 示例数据
**它怎么做**：灵感墙为空时，hero 下面直接写"写一句话、贴一个链接，或者把图片和视频拖进来"；**首次安装给一整套示例数据**，右上角常驻「示例数据 · 清空」。
**我们现在的差距**：空态是"看板上还没有推荐卡 / 切到问答池挑一个方向"。装完是空的，新用户不知道先干什么。
**怎么落**：复用 `examples/library` 生成 3 张示例卡（一张有来源截图、一张已成熟、一条问答池方向），首次启动播种，右上角给「示例数据 · 清空」。注意示例卡要能一键全清、且不污染素材库计数。
**成本**：低｜**收益**：高（插件冷启动决定留存）

### 2.9 双视图 + 底部悬浮筛选条
**它怎么做**：同一批灵感两种看法（散落画布 / 信息流瀑布），底部一个玻璃胶囊条：`[散落|信息流] | 全部 图片 视频 网页 金句 笔记 | +`。
**我们现在的差距**：看板 / 问答池已分段，但**没有"按类型筛"和"按成熟度筛"**，也没有列表视图。
**怎么落**：不加画布（见第 5 节），只加「看板 ↔ 列表」切换 + 底部或 sub-toolbar 的筛选 chips（推荐/我的 · 未动/在写/已成熟 · 有人问过）。
**成本**：低｜**收益**：中

### 2.10 键盘全流程
**它怎么做**：`Cmd+Z` 撤销、`Enter` 发送（兼容中文输入法 `isComposing`）、`Esc` 分层、聚焦时方向键翻图、Tab 到屏幕外卡片时相机自动跟过去。
**我们现在的差距**：聚焦页有 `Ctrl/⌘+Enter` 暂存、`Esc` 退出，其余没有。
**怎么落**：看板 `↑↓←→` 移动焦点 + `Enter` 打开；改稿 `Cmd+S` 保存、`Cmd+Enter` 送渲染。
**成本**：低｜**收益**：中

## 3. 视觉效果：10 条可抄

### 3.1 首屏是一句话，不是工具栏
**它怎么做**：33px / 字重 300 / 字距 -0.015em 的三行陈述句，数字加粗、句子里嵌 36px 圆形小图：
> 还有 **12 个灵感** 等你成稿，**3 条内容** 排在本周，你已经连续记录 *14 天*。

**我们现在的差距**：选题页顶部是 sub-toolbar（看板/问答池/聚焦 + "本地素材 N 条"），信息齐但没有"今天该做什么"。
**怎么落**：看板顶部加一行陈述句（今日待处理 N 张 · 上次记录 X 天前 · 问答池新增 M 个方向），数字可点=筛选。放在 `pms-scroll` 第一屏，不占固定高度。
**成本**：低｜**收益**：高（这是产品的"人味"）

### 3.2 卡片类型化：一屏能认出三种东西
**它怎么做**：同一面墙三种卡——`quote` 用宋体 20px 大字 + 22px 内边距；`note` 带底纹横线（`is-ruled`）+ 4:3 图；`media` 图内缩 6px、圆角 14px、底部 11.5px 灰字来源。
**我们现在的差距**：所有卡一个模板：badge 行 + h2 + p + meta，只靠文字区分。
**怎么落**：拆两类就够——**「有人问过」卡**（左侧或顶部带来源截图缩略图，你已有 `sourceAssetId`，天然可做）、**「我的判断」卡**（`latestThesis` 用宋体 18-20px 显示，像引言）。`pms-card` 加 `--quote` / `--evidence` 两个变体。
**成本**：低｜**收益**：高（辨识度 + 美感同时提升）

### 3.3 让拉丁衬线管数字
**它怎么做**：`--latin-serif: "Iowan Old Style", Palatino, Georgia`，日历大数字 64px、时长 22px、排名 16px、字数都用它；连续天数用斜体。
**我们现在的差距**：数字全走系统无衬线，看板计数、字数、时间没有节奏差。
**怎么落**：`tokens.css` 加 `--pms-font-serif-latin`，只用在：阶段计数、字数/页数、日期时间、聚焦进度「01 / 11」。
**成本**：极低｜**收益**：中高（编辑感）

### 3.4 一屏一个实心主按钮，状态只用小圆点
**它怎么做**：主色只有一个（`--primary`），一屏只出现一处实心按钮（复制脚本 / 标为成熟 / 下一条）；状态用 7px 小圆点 + 浅底胶囊（琥珀=大纲、蓝=草稿、紫=待发、绿=已发）。
**我们现在的差距**：卡工作区底部一排 5 个按钮（追加保存 / 暂存 / 标为成熟 / 删除 / 进入聚焦），其中只有"标为成熟"是 primary，方向对；但 badge 语义有 6 种，视觉权重接近。
**怎么落**：核对规范页，写死一条"每屏至多一个 filled primary"；badge 里只有"成熟""模型已连接"允许带色底，其余走 `--outline`。
**成本**：极低｜**收益**：中

### 3.5 骨架屏 / 扫光 / 显影三件套
**它怎么做**：
- 正文骨架 = 12 行不等宽圆角条（`nth-child(3n)` 72%、`5n` 88%），shimmer 1.6s / 220% 位移
- 未生成的图格 = shimmer 扫光 + 巨大编号水印（`01`）
- 图加载完 = `blur(10px) scale(1.03)` → 清晰，0.9s（"显影"）

**我们现在的差距**：只有 `pms-skeleton` 卡片骨架。
**怎么落**：改稿正文用 12 行骨架；渲染阶段每页 PNG 生成完播一次"显影"；未生成页显示页码水印。
**成本**：低｜**收益**：中高（尤其渲染阶段，本来就有等待）

### 3.6 入场级联 + hover 微旋转归零
**它怎么做**：卡片首次出现从"朝中心反方向偏移 + scale(.8) + 随机 ±10°"落位，stagger 32ms、上限 620ms；hover 时旋转归零、抬 4px、scale 1.025（`cubic-bezier(.2,1.3,.4,1)`）；拖拽时旋转减半、scale 1.05、投影加深。
**我们现在的差距**：网格静态，无入场。
**怎么落**：只借"级联入场 + hover 抬升归零"，一套 2 个 keyframes。**不要**抄随机旋转（纸感我们已经用在聚焦页，看板再加会乱）。
**成本**：极低｜**收益**：中

### 3.7 容器查询而非媒体查询
**它怎么做**：`.md-root { container: md-root / inline-size }`，按 1020 / 780 / 620 / 560 四档改布局：窄了助手变抽屉、bento 变单列、日历隐藏统计、导航可横滑。
**我们现在的差距**：已有 `container-name: pms-panel` + 780px 断点（聚焦页收分析栏），但只此一处。
**怎么落**：把 `pms-body` 设成容器，卡工作区（780：分析栏抽屉化）、改稿（820：侧栏改底部 tabs）、看板（640：单列）三处统一。
**成本**：低｜**收益**：中高（DSH 面板宽度不可控）

### 3.8 玻璃浮层要克制
**它怎么做**：`--glass: color-mix(card 72%, transparent)` + `backdrop-filter: blur(24px) saturate(160%)`，只用于**浮在内容之上的条**（顶部导航、底部工具条、卡片操作圆钮）。
**我们的判断**：我们的纸感 + 米白更适合"实底"，不该满天飞玻璃。**可以借的只有一处**：看板底部/顶部的视图切换条做成悬浮玻璃，其余保持实底。
**成本**：低｜**收益**：低（可选）

### 3.9 邮票（stamp）——好看的陷阱
**它怎么做**：`mask: radial-gradient(...)` 打齿孔，4:5 比例，日历每天一格、连续记录可见。
**我们的判断**：机制很妙，但**只在有"连续行为"时才成立**。我们目前没有每日节律（用户是想起来才写），硬做会变成装饰。**唯一可考虑的场景**：聚焦模式退出页显示"这一轮处理了 11 张"的一枚小票。
**成本**：低｜**收益**：低，建议缓做

### 3.10 减少动效是硬要求
**它怎么做**：`@media (prefers-reduced-motion: reduce)` 全局把 animation/transition 压到 0.01ms；JS 里 `reducedMotion()` 直接跳过 FLIP 和相机动画。
**我们现在的差距**：规范页没有这一节。
**怎么落**：`styles.css` 末尾加统一媒体查询；`tokens.css` 里把 duration 令牌在 reduce 下置 0。
**成本**：极低｜**收益**：中（无障碍 + 插件跑一整天的体感）

## 4. 功能：10 条可抄

### 4.1 两段式生成：先出"结构方案"，再并行展开
**它怎么做**：先一次轻量调用产出结构化 plan（标题、封面大字、outline、每张配图的 prompt 与 anchor、六格分镜的镜别/秒数/口播），落库后**文章和所有图片同时开工**（worker 池并发，单张 429 指数退避）。
**为什么适合我们**：我们的"生产改稿"现在是 LLM 出全文 + 规则引擎分节，HANDOFF 里自己也写了"分段和加粗比较粗，长文还要人改"。
**怎么落**：把生成拆成 `plan` / `expand` 两次：
1. `plan`：出 3 个标题候选 + 每节要点 + 配图位（**不动句子**，符合"原句不改"）
2. 用户挑一版（或直接取第一版）
3. `expand`：按 plan 展开成文，配图并行匹配

这样既解决分节粗糙，又把"结构"变成可审的东西——和我们的"人工 gate"哲学一致。
**成本**：中高（改 `runtime` 生成流程）｜**收益**：最高（直接提升成稿质量）

### 4.2 plan 失败降级，不整单失败
**它怎么做**：模型挂 → `fallbackPlan` 模板继续跑，界面标注"结构草稿"；生图未配置 → 资产 `skipped` 但文字照出。
**我们现在的差距**：本地预览引擎已是一个全局降级，但没有"某一环失败仍出半成品"。
**怎么落**：给每个产物标 `pending/running/done/failed/skipped` 五态，界面允许"半成品 + 局部重试"。
**成本**：中｜**收益**：中高

### 4.3 单页/单块重生成
**它怎么做**：封面、每张配图、每一格分镜都能单独 `regen`；失败格右下角直接是「没画成，重画」小按钮。
**我们现在的差距**：渲染只能整篇重出。
**怎么落**：`pages` 表加状态与 `version`，支持单页重渲染、单页换图；素材清单里每张图可"换一张"。
**成本**：中｜**收益**：高（改一页不用重跑整篇，省时省心）

### 4.4 规则层：复盘 → 建议 → 写进规则 → 导出 Skill
**它怎么做**：从数据里提炼"建议"（待确认）→ 点「写进规则」→ 规则参与后续 prompt → 可整包导出成 DSH Skill。
**为什么适合我们**：我们反复手动改的东西其实很固定（标题别超 20 字、结尾只留一件事、价格一律标待确认）。这些现在散在提示词里，用户看不见也改不了。
**怎么落**：加一张 `writing_rules` 表（name / rule / status: proposed|active / source），在改稿侧栏给"规则"页签：可查看、停用、手动加一条。规则拼进 prompt 最前面。
**成本**：中（表 + 侧栏 + prompt 注入）｜**收益**：高（"越用越像你"的唯一路径）

### 4.5 生成前的轻量选项，而不是进去再后悔
**它怎么做**：「一键成稿」按钮旁边一个 checkbox `生成图片`；不勾就只出文字，之后仍可单张补画；设置里可改默认。
**我们现在的差距**：是否带图、用哪套版式，要进到渲染页才知道。
**怎么落**：在「进入内容生产」旁放选项条：`体裁（长文/图文）· 配图（自动/不要）· 版式（头像绿/深蓝金/公文风）`，带默认记忆。
**成本**：低｜**收益**：中

### 4.6 示例数据 + 一键清空
同 2.8。单独列出来是因为它对**插件分发型产品**是留存关键：装完是空的，用户 30 秒内没看到价值就卸载了。
**成本**：低｜**收益**：高

### 4.7 文案集中，即便只做中文
**它怎么做**：所有界面文案走 `t('中文原文')` + `client/en/` 词典。好处不是英文，是**文案可检索、可批量改、可审校**。
**我们现在的差距**：中文散在 1926 行 `app.tsx` 里。
**怎么落**：不必上 i18n 框架，抽一个 `copy.ts` 常量表按模块分组即可。改文案从"改代码"变成"改表"。
**成本**：低（一次性搬 200 条）｜**收益**：中

### 4.8 版本自查 + 顶栏小胶囊
**它怎么做**：每小时最多一次读 npm 版本号，有新版本顶栏出现 `↑ v2.7.1`，设置底部显示当前版本与升级命令。
**怎么落**：读我们自己包的 registry 版本，顶栏加一个胶囊；点了展开升级命令。注意别做成打扰。
**成本**：低｜**收益**：中（插件更新率）

### 4.9 软依赖别的插件
**它怎么做**：装了 `dsh-better-sidebar` 就额外注册一个右侧 tab；没装就静默跳过，不进顶层 `inject`（`index.jsx:232-253`）。
**为什么值得抄**：我们的入口是 `sidebar.panellist`，用户一旦装了接管侧栏的插件，我们的入口就没了——这是他们 issue #10 的真实故障。
**成本**：低｜**收益**：中（防御性）

### 4.10 ops 白名单 + 回执 + 幂等
**它怎么做**：模型只能发白名单 op；每个 op 返回一句回执；写操作带幂等键。
**我们已有的**：`advanceCard` + `client_op_id` 唯一索引，这块比它做得更硬。
**可补的**：把"模型/工具能做什么"显式列成 op 白名单文档，和界面动作共用一套，避免工具侧和 UI 侧行为漂移。
**成本**：低｜**收益**：中

## 5. 不该抄的 5 条

| 不抄 | 原因 |
| --- | --- |
| **无限画布（散落 + 相机 + 惯性）** | 实现很漂亮（弹簧相机、缩放跟随光标、相关卡自动入镜），但认知成本高、可访问性差、移动端几乎不可用。我们的"聚焦模式一次只看一张"已经解决了它想解决的问题：**别让用户在一堆东西里挑**。 |
| **常驻 320px 助手栏** | 他们自己在 1020px 就把它收成抽屉了。DSH 面板常态 700-900px，常驻会把稿面挤死。我们要做对话式改稿，就做成**选中后浮起**或**底部一行**，不常驻。 |
| **排期 + 发布闭环** | 与硬规则冲突：不向平台发布、价格一律待确认。日历可以看（"什么时候写"），但不能长成"发布工作流"，否则产品重心会漂。 |
| **满屏玻璃拟态 + 42s 漂移光斑** | 他们的底子是"轻玻璃 + 彩色氛围"，我们是"纸感 + 安静"。混在一起会两边都不像。最多借一处悬浮切换条。 |
| **15 种博主风格预设** | 数量是他们的护城河（配合账号导入），不是我们的。我们只有一个账号一种声音，应该做**栏目预设**（问答 / 观点 / 案例），而不是人设预设。 |
