# 交互手感 & 卡片信息设计：具体改法

> 承接 `media-desk-teardown.md`，这篇只回答两件事：**手感怎么调**、**卡片上到底该放什么**。所有条目都指到具体文件与数值。

---

## 一、交互手感

### 1.0 先定位问题：我们的"顿"不在动画，在数据

`app.tsx` 里几乎每个写操作都是这个形状：

```ts
await rpc('appendThought', {...})
setDetail(await rpc<CardDetail>('getCard', { cardId }))
// 或者
void refresh()          // 重新拉 bootstrap，整棵树重渲染
```

- `save()` 里追加一条原话 → 等一次 `getCard` 才看到它出现。
- `mature()` / 删除 → `refresh()` 拉全量 bootstrap，看板整个重排。
- 聚焦推进已经优化过（`listBoardIds` 轻量列表），但普通卡片视图没有。

**结论：先把"等网络"从视觉路径上拿掉，再谈缓动曲线。** 动画再顺，等 400ms 才有反馈就是顿。

### 1.1 乐观更新（优先级最高）

| 动作 | 立刻做什么 | 失败怎么收 |
| --- | --- | --- |
| 追加原话 | 以"待同步"节点插入时间线（opacity .55 + 左侧小圆点脉动），清空输入框，按钮恢复 | 节点标红 + toast + 把文字放回输入框（别丢用户输入） |
| 标为成熟 | 卡片状态点变绿、阶段计数 +1、toast 立刻出 | 回滚状态 + toast「没成功，再试一次」（幂等键已在，重试安全） |
| 删除卡 | 卡片先从网格消失（高度塌陷 200ms） | 原位淡入回来 + toast |
| 关联素材 | 勾选即时变，不等 RPC | 取消勾选 + 行内错误 |

实现方式：不要 `refresh()` 全量。给列表加一个 `patchCard(id, patch)`，只替换受影响那条；后台再静默 `refresh()` 校准。media-desk 的 `mergeProduction` 就是这个做法（`desk.js:123`）。

### 1.2 时长纪律（三档，不要混）

| 时长 | 用途 | 例子 |
| --- | --- | --- |
| 0–100ms | 按下/悬停的"触摸感" | `:active { transform: scale(.97) }`、hover 背景 `80ms` |
| 150–250ms | 颜色、边框、透明度 | 选中态切换、badge 变色、按钮 disabled 变化 |
| 300–500ms | 位移、展开、转场 | 抽屉、放大、卡片进出 |

超过 500ms 的等待**必须给事实型进度**（第几块、多少字、哪一步），不能只给 spinner。

### 1.3 缓动分工

```css
--pms-ease-out: cubic-bezier(.2, .8, .2, 1);      /* 进出、位移默认 */
--pms-ease-spring: cubic-bezier(.2, 1.3, .4, 1);  /* 落位、弹层出现，幅度要小 */
```

- 弹性曲线**只给"出现"用**（弹层、toast、放大格），不要给"消失"用——消失用弹性会显得拖沓。
- 线性只给进度条和 shimmer。

### 1.4 阈值与误触抑制

- 拖动/滑动判定：**4px 阈值**，没超过就当点击（media-desk `canvas.jsx:284`）。
- 超过阈值后**抑制后续 click**（`suppressClick`），否则拖完会顺带打开卡片。
- 我们的卡片整体是 `<button>`，点击面积大，更应该加这条。

### 1.5 输入框的五个细节

1. 自增高到 140px 后内部滚动（不要无限长）。
2. `Enter` 提交、`Shift+Enter` 换行、**判 `isComposing`**（中文输入法选词时按回车不能直接提交）。
3. **失焦即保存**，不要让用户找"追加保存"按钮（按钮保留，作为显式路径）。
4. `:focus-within` 时容器 `box-shadow: 0 0 0 1px var(--pms-primary)` + `translateY(-1px)`，让"我正在写"可感知。
5. disabled 用 `opacity: .28`（或 `.5`），**不要换成灰底**——灰底会被读成"另一种按钮"。

### 1.6 按钮不要跳字

「追加保存」→「保存中…」会让整行按钮位移，这是最廉价的廉价感。

- 做法 A：`min-width` 固定，文案长度变化不挤压。
- 做法 B：文案不动，只在左侧图标位放 12px spinner。
- 禁用原因要**可见**：现在只靠 `title`，触屏看不到。成熟按钮禁用时，在下方给一行 12px 说明（"先写一句，或关联一条素材"）。

### 1.7 Esc 分层 + 焦点归还

已有 `FocusConfirm` 的 inert + Tab 陷阱 + 焦点归还，这是全项目手感最好的部分，**推广到所有层**：

层级栈：确认弹窗 → 素材抽屉 → 放大阅读 → 卡片 → 看板。
Esc 只消费最上层，不允许一键退到底。用一个小 hook `useEscapeStack()` 统一管。

### 1.8 滚动语义

- 追加原话后：时间线滚到底（并让新节点有一次 200ms 的高亮底色衰减）。
- 生成完成：正文滚回顶部（"从第一句读起"，media-desk `studio.jsx:307`）。
- 切换卡片：各自记住滚动位置（`Map<cardId, scrollTop>`），返回时恢复。
- 退出聚焦回看板：恢复看板原滚动位置，不要回到顶部。

### 1.9 排版不跳（CLS）

- 图片/封面：固定 `aspect-ratio` 占位，不要等图load。
- 徽标行：预留一行高度，数量从 3 变 1 时卡片不塌。
- 骨架：保留最终轮廓（已有 `StudioSkeleton`，方向对）。

### 1.10 回执要有信息量

不要"保存成功"，要"已追加 1 条原话 · 共 4 条"。参考 media-desk 的 `receipts`：每个 op 返回一句人话，界面直接显示，可点跳转。

### 1.11 同一时刻只允许一个"进行中"

现在 `StudioSkeleton`、卡内"整理中"badge、按钮 spinner 可能同时出现。规则：**进行中指示必须出现在动作发生的位置**，全局只保留一个。

## 二、卡片信息呈现

### 2.1 诊断：现在一张卡上有几层信息

`app.tsx:861-873` 的实际结构：

```
[推荐/我的]  [4 人问过]  [进行中]        ← 3 个胶囊，权重相同
标题（15px，1-2 行）
latestThesis（13px，最多 8 行）          ← 卡片被文字吃掉
[种子阶段]                               ← 第 4 个状态词
```

问题不是"信息多"，是**四件事都在抢同一层**：

1. **语义重复**：`statusLabel`（进行中/待写正文/改稿中）和 `maturityLabel`（种子/构思中/成形/可生产）都在回答"到什么程度了"。用户要在脑子里做一次映射。
2. **摘要过长**：`-webkit-line-clamp: 8` ≈ 卡片高度的一半以上，一屏只能看 6 张。
3. **没有时间**：`updatedAt` 在数据里，卡上看不见。而"哪张该现在写"很大程度由"多久没动"决定。
4. **没有理由**：看板声称按"最常被问、最近还在问、还没写过"排序，但卡面看不出任何一条。
5. **没有类型视觉**：证据卡（有来源截图）和判断卡（有 thesis）长得一样。

### 2.2 目标：三层信息节奏

| 层 | 时间预算 | 回答的问题 | 放什么 |
| --- | --- | --- | --- |
| L1 扫 | 0.5 秒 | 这张讲什么？ | 标题（2 行）+ 类型色条/缩略图 |
| L2 判 | 2 秒 | 为什么现在写它？ | 一行证据（谁在问 / 缺什么 / 多久没动） |
| L3 读 | 点进去 | 我该说什么？ | 原话、分析、素材 |

卡上只放 L1 + L2。所有 L3 一律进卡片。

### 2.3 五条具体改法

**① 标签 3 → 1，且随状态换**

只留最有说服力的那一条，不做并列：

| 卡的状态 | 显示 |
| --- | --- |
| 推荐、没写过 | `4 人问过`（需求真实） |
| 写过原话、未成熟 | `在写` |
| 成熟 | `可生产`（唯一的 success 色） |
| 我的卡 | 不加标签，改左侧 3px 色条区分来源 |

**② 摘要 8 行 → 2 行，且换内容**

不要截 `latestThesis` 的开头（开头多半是"同学问的是……"这种铺垫）。改成：

- 后端给一句 `digest`（20–30 字），或在 `analysis.thesis` 存在时取第一句；
- 没有则回退到 `latestThesis`，clamp 2 行。

**③ 底行统一成"事实带"，不再用胶囊**

```
● 可生产  ·  4 人问过  ·  3 天前动过
```
11.5px / tertiary / `·` 分隔 / `font-variant-numeric: tabular-nums`。
胶囊是"标签"，这里是"事实"，视觉上必须区分开。

**④ 两种卡型（成本低、辨识度提升最大）**

- **证据卡**（有 `sourceAssetId`）：顶部 4:3 缩略图（高 96px，`object-fit: cover`，圆角 8px，`margin: -8px -8px 8px`），标题 2 行。天然告诉用户"这是学员问的"。
- **判断卡**（有 thesis、无截图）：`latestThesis` 用宋体 18px / 行高 28 显示一句，标题降为 12px tertiary 在上方。
- 类名：`.pms-card--evidence` / `.pms-card--quote`，都挂在现有 `.pms-card` 上，不新增组件。

**⑤ 分组 + 三档密度**

分组（默认按此，不做成可配置）：
- `该写了`：成熟 + 超过 7 天没动（段头：13px + 计数 + 一句"再不写就要重新想"）
- `在写`：有原话、未成熟
- `搁置`：shelved

密度三档，按容器宽度自动降级，不做用户开关：
- **舒展**（≥900px）：带截图，卡高 ~200px
- **标准**（640–900px）：色条 + 标题 + 证据行，卡高 ~132px
- **紧凑**（<640px）：单行，`● 标题 ····· 4 人 · 3 天`，行高 44px

### 2.4 工作区卡头也要收敛

现在是 `标题 + [状态] + [4 条原话] + [模型分析]` 三个并列胶囊。

建议：
- 状态 → 小圆点 + 文字（不要胶囊底）
- 引擎徽标**只在不健康时出现**（"本地预览引擎"该常驻，因为它是降级；"模型分析"正常态可省）
- 原话数移进时间线标题：`4 条原话`（作为 section 头，而不是卡头标签）

### 2.5 分析栏：6 段全展开 = 没有重点

现在"核心判断 / 故事与案例 / 还缺什么 / 视角与反视角 / 继续问 / 相关素材"同时铺开。

建议：
1. 顶部加一句结论式提示：`现在最该补的是：一个具体案例`（取 `analysis.gaps[0]`）。
2. 默认只展开「核心判断」和「还缺什么」——这两个直接决定"能不能写"。
3. 其余四段折叠成一行标题 + 计数（`故事与案例 2` / `相反视角 3` / `继续问 4` / `相关素材 1`）。
4. 折叠记忆到 `localStorage`，别每次都重开。
